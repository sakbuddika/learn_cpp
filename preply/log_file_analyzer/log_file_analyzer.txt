Log File Analyzer
Overview
In this project you’ll build a command-line application that reads application logs from a text
file, analyzes them, and produces a summary report.

Classes and separate compilation: designing classes with clear responsibilities, and
splitting declarations (.h) from implementations (.cpp).
File streams: reading files with std::ifstream and checking stream state to detect missing
or unreadable files.
String parsing: splitting and trimming text using std::string operations such as find,
substr, or std::getline with a delimiter.
Standard containers: choosing between std::map, std::unordered_map, and std::vector
based on what each operation needs.
Sorting with custom comparators: ordering results with std::sort and a lambda.
Const-correctness and references: passing objects efficiently and marking functions
that don’t modify state as const.
Error handling: deciding when to skip bad input, when to report it, and when to stop the
program.
Requirements
1. Read log entries from a file named logs.txt.
2. Each valid entry has the format: YYYY-MM-DD HH:MM:SS | LEVEL | Message
3. A valid severity level is exactly one of INFO, WARNING, or ERROR. Any other level
(for example DEBUG) makes the entry malformed.
4. Count the total number of valid entries, the number at each severity level, and the number
of malformed lines.
5. Identify the five most frequent ERROR messages and their counts. If messages are tied,
order them alphabetically.
6. Organize the program using classes and appropriate data structures.
7. Handle a missing file, an empty file, and malformed entries gracefully. The program
shouldn’t crash, and it should tell the user what happened.
8. Separate the program into appropriate header and source files.
You’re free to choose your own design and implementation.
